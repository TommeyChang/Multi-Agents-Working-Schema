# SUBAGENT-details.md — 子代理的查阅面

主文件 `SUBAGENT.md` 是**动作面**（额度、职能、门禁、复用、禁则）；这里放**扇出算法与派单模板**。

## 六、扇出

**多开鼓励，但有定额。只闸两处。**

- 数量按 `A ≈ P ÷ T` 反推，不得突破整机预算；
- 按**互不重叠文件白名单**扇出；
- **不触库的活可任意并行**（纯域逻辑、契约、静态检查、文档、局部单测）。

| 闸 | 内容 |
|---|---|
| **共享面** | 清单见**工程绑定** §共享文件（共享面逐工程不同，故不在本文件列路径）⇒ **串行，或由派单方单点改** |
| **触库测试并发** | 固定库名修复前 ≤ 2；修复后放宽到 4 |

**怎么知道能同时开几个**：查**并行派单建议**（`coord ready --fanout`）——
它把可认领条目排成互不重叠的批次，并标出超预算暂缓的那些。
**同批可一次派完，不同批必须等前一批腾出文件。**
不要凭肉眼比对白名单——那正是会出错的地方。

**预算逐线给**（线是工作面，工作量天然不均）：`coord quota --line D --budget 2`。
**未批预算的线派不了活**——**这是闸，不是提醒**：`Quota` 默认即启用，
没批预算的线在 `claim-dev` 与 `ready` 两处都出不来（实测过旧默认 `enabled=False`：
没批任何预算照样能派单，于是"能开几个"只剩散文）。

**开子代理前先领凭证**（**按条目一张**）：

```
coord dispatch --role tech-lead:TL-D:D --task T-D-1   # 领授权 → 拿到 lease_id
coord grants                                          # 现在手上有几张、还剩多少额度
```

凭证就是一条**租约**：可数（`active_grants` 是唯一答案）、有界（超过
`subagent_max_per_dispatcher` 即拒）、**会过期**（TTL 到自动回收，避免"授权挂着但人早走了"）、
能对账（在办条目没有在手授权 ⇒ 审计报 `E_UNAUTHORIZED_DISPATCH`）。
**子代理默认不得自开**（没有派单权的角色派不出单），**同条目复用即可**（复用不新开）。

**唯一的例外：`dev` 可以再开 `dev`**（2026-10-04 用户定：「dev 是可以开 dev 子代理的」）——
用于本条目的内部分工／扇出，按 §二 的额度计数（该额度**按派单方**算，
所以 dev 再开 dev 不会绕过上限）。这是**dev 的执行自由**，不是对禁则的松动。

**禁则只约束两端**：**commander／parent 会话不得直开 dev**（10-04 用户定——
commander 的正当动作止于立案行／冻结口径／取号／合入／推送／台账对账）。
**线 pm 能否开 dev：用户口径未规定**，留待用户裁定，**勿由会话自行推定**。
另有**总量上限**兜共享资源（触库并发、CPU、内存）。

**预算从哪来**：`python3 tools/calibrate.py` 逐维量（触库／**测试**／CPU／内存／磁盘），
取最小者为 W。其中**测试维是唯一非合成的一档**，跑的就是上面那条快跑通道
（`-m "not db"`——真库档按 `docs/TESTING.md §3` 不得并发，故不在该维）。
**标定必须在没有别的会话跑测试时做**：实测有并发时同一维墙钟在 8.3s~13.8s 之间乱跳，
拐点被噪声推到最后；脚本检出负载会自己标「不可信」，**那时的数字不得据以写配额**。

各子代理用**自己的 scratch 前缀**。

> **触库并发为什么不能无脑加**：并发迁移在 8 路下实测耗时增加约 264%。

**线间不设串行闸。**
跨线条目**不得以同域、同文件、在途为由建立串行依赖**，也不要求他线回执。
**线间只有范围知会**——不阻断、不等待。
**并发控制按线内**：各线自行保证在办条目与子代理不过并发预算。
同文件跨线冲突**按 git 合并处理**。

## 十、派单模板（两式：新开 ＝ 完整；续派 ＝ 增量）

**判据**：可复用子代理开工即启动、公共信息一次预置（§七「预热」）——
所以模板分两式，**续派不重复预置**。

### 式一 · 新开（完整模板，逐项填写，**缺项不派**）

```
【条目】T-X-N
【规模】预期文件数 ≤ 6；净新增 ≤ 约 400 行；超限则按互不重叠白名单拆
【白名单】<精确清单——子代理只能动这些>
【不动清单】<明确禁改：生产代码 / 共享文件 / 状态文件 / docs/ / 公约文件 …>
【职能】impl | test | verifier
【复用】派单前查在册可续者；同条目、同分支、同白名单、同职能一律续派；未送达方可新开
【空转】派单前双检；禁 sleep 与轮询；零产物须回报根因并计入额度；小活并批或自办
【门禁】命令原文 ＋ 退出码 ＋ 摘要数字 ＋ 原始输出落盘路径；报「既有红」须附同口径对照
【扇出】按 A ≈ P ÷ T 反推；互不重叠白名单；不触库可任意并行；
        共享文件串行或单点改；触库并发 ≤2（修前）／≤4（修后）；单对话累计 ≤ 10
【回报】条目号 / 分支 / commit / 改动文件 / 门禁命令与退出码与摘要与落盘路径 /
        关键自测数字 / 「我未验证的假设」清单 / 已知边界与残留
【越权禁止】git merge 与 push · accept · 编辑状态文件 · 装 hooks · 动公约与 docs/
```

---

### 式二 · 续派（增量模板）

```
【条目】<条目号>
【本轮】<只写这一轮要做什么——一行>
【照旧】白名单／不动清单／验收以 `coord show <条目号>` 现取为准，不重复预置
```

**为什么续派这么短**：粘贴具体任务全文＝把**快照**塞进代理上下文——
条目修订后它手上的口径就陈了，而且复用得越久上下文越脏。
判据单源在协调器，下达只给**引用 ＋ 增量**。
