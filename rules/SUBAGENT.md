# SUBAGENT.md — 子代理边界

> 派单、职能、扇出、复用、额度、空转。**派单方必读。**

---

## 一、铁律：主对话不阻断

**长任务一律后台派单**，派完即回主对话，**禁同步等待**。

长任务包括：实现、写测试、调研、大范围检索、审计。

**理由**：独立会话**只有用户能开**，是最稀缺的资源。
主对话被一个长任务占住，该会话就停摆——不能派新单、不能收回报、不能合入。

**「不阻断」的边界是「禁无界占用」，不是「禁占用」。**
派单方的**有界短动作**照旧同步做：

> 读回报、独立重跑门禁、合入、回标、解冲突、收在跑清单。

**每次只做单个条目的这一段。**

---

## 二、额度

| 量 | 定义 |
|---|---|
| `T` | 派单方处理**单个条目**的同步段时长 |
| `P` | 单个子代理的时长 |
| `A` | **同时在后台运行的子代理数**，约等于 `P ÷ T` |

**`A` 不是「不限」。** `T` 的第一约束是**回报体积**，第二约束是**整机预算**。

**硬上限**：一个对话开启的子代理**累计不超过 10 个**。

- 累计计数：**一经开启即计数，含已终止者**；
- **续派不新增计数**；
- 达 10 而仍需推进 ⇒ **只可复用已有子代理，或由派单方自办**，禁开第 11 个；
- 派单前核实当前累计数，并在派单记录中留痕。

---

## 三、规模

一个子代理 = **1 个条目**，另有下列额度：

| 项 | 额度 |
|---|---|
| 文件 | ≤ 6 |
| 净新增 | ≤ 约 400 行 |
| worktree／分支 | 1 / 1 |

超限按**互不重叠文件白名单**拆多开。

**同缝例外**：同一 feature 的同缝接线（同一装配缝、同一组文件）可单条超限，须**同时**满足：

1. 文件互不重叠已由白名单保证；
2. 拆分会**重建已消除的串行面**；
3. 超限在回标中**显式披露**实际行数与不拆理由。

**已终态的条目不回填拆分。**

---

## 四、职能

| 职能 | 做什么 | 不做什么 |
|---|---|---|
| `impl` | 实现 ＋ 契约级最小测试 | **不写验收判据测试、不宣称验收通过** |
| `test` | 依验收标准独立写测试（含负例与空断言／顺序依赖自检） | **不改生产代码** |
| `verifier` | 对抗复核：独立复跑门禁、复现关键数字、查基座是否最新、**专找假绿** | **不改交付物** |

**小条目允许 `impl+test` 同体；`verifier` 必须独立**（派单方自任亦可）。

---

## 五、门禁

**允许跑、禁止自证。**

- 子代理**必须**自己跑测试与 lint；
- **回报 = 命令 ＋ 退出码 ＋ 摘要数字 ＋ 原始输出落盘路径**；
- **原始输出必须落盘**，供派单方随查——**证据可核不放松，回报体积有界**；
- **禁**用管道或串联吞掉退出码后当结论；
- **禁**把红说成「既有红」——须给主干或前一提交的**同口径对照实证**；
- **派单方合入前必须独立重跑**，不信自述。

### 提交前先过**界内**闸

改动落盘后、提交前，用提交闸对**账**——它读协调器里该条目的白名单与不动清单，只读、不写：

```
python3 tools/commit_gate.py --task <条目号>            # 默认看暂存区
python3 tools/commit_gate.py --task <条目号> --range <base>..HEAD
```

| 判 | 内容 | 退出码 |
|---|---|---|
| **BLOCK** | 改动文件**不在白名单**内；或**命中不动清单** | 1（拒绝提交） |
| **WARN** | 动了设计面但本批没同批改文档；条目白名单为空 | 0（留痕放行） |

**界内是结构约束，不是自觉**：越界改动在这里就被挡住，而不是等到合并时才被打回。
没批白名单＝条目本身没定稿——那是**条目的问题**，告警留痕，别拿它当"文件都合规"。

### 测试范围：**按影响面测，不全量测**

**测试是全仓最重的负载**——实测 4939 例；`broker_gateway` 一个域占 2774 例（56%）。
**域粒度太粗**：改 `broker_gateway/` 下**任意一个文件**就触发整个域（实测 2774 例，占全仓 56%）。
日常自测按**影响面**收窄——**范围由本体系自己算**，门禁入口也是本体系自己的：

```
python3 tools/gate.py --changed <改动的文件…>     # ruff ＋ 影响面 pytest（快跑通道）
```

三档，**从细到粗**：

| 档 | 判据 | 含义 |
|---|---|---|
| **直连** | 测试 `import` 了该模块 | 最省也最准 |
| **同名** | 测试文件名含该模块名（`follow.py` → `test_*follow*.py`） | 次之 |
| **兜底** | 两档都没命中 ⇒ **退回整域** | 宁多跑，不可漏跑 |

**它是估计，不保证零漏测**：静态 import 反演看不到动态 import、间接依赖、fixture 链。
所以口径按时点分：

| 时点 | 口径 |
|---|---|
| 交付前自测 | `gate.py --changed …`（受影响面） |
| 合并前 | 派单方**独立重跑同口径** |
| **发布前** | **`gate.py --scope full`——全量。这条不因收窄工具改变** |

**收窄必须报口径**：命令、退出码、用例数、落盘路径，**一样不能少**。
**静默少跑是这类工具最危险的失败形态**——收了窄而不报，等于把漏测藏起来；
派单方按同一口径复跑，一处对不上就退回。

## 六、扇出

**多开鼓励，但有定额。只闸两处。**

- 数量按 `A ≈ P ÷ T` 反推，不得突破整机预算；
- 按**互不重叠文件白名单**扇出；
- **不触库的活可任意并行**（纯域逻辑、契约、静态检查、文档、局部单测）。

| 闸 | 内容 |
|---|---|
| **共享面** | 清单见**工程绑定** §共享文件（共享面逐工程不同，故不在本文件列路径）⇒ **串行，或由派单方单点改** |
| **触库测试并发** | 固定库名修复前 ≤ 2；修复后放宽到 4 |

**怎么知道能同时开几个**：查**并行派单建议**（`coord ready --fanout`）——
它把可认领条目排成互不重叠的批次，并标出超预算暂缓的那些。
**同批可一次派完，不同批必须等前一批腾出文件。**
不要凭肉眼比对白名单——那正是会出错的地方。

**预算逐线给**（线是工作面，工作量天然不均）：`coord quota --line D --budget 2`。
**未批预算的线派不了活**——决策缺口要暴露，不能靠统一默认值静默填上。
另有**总量上限**兜共享资源（触库并发、CPU、内存）。

**预算从哪来**：`python3 tools/calibrate.py` 逐维量（触库／**测试**／CPU／内存／磁盘），
取最小者为 W。其中**测试维是唯一非合成的一档**，跑的就是上面那条快跑通道
（`-m "not db"`——真库档按 `docs/TESTING.md §3` 不得并发，故不在该维）。
**标定必须在没有别的会话跑测试时做**：实测有并发时同一维墙钟在 8.3s~13.8s 之间乱跳，
拐点被噪声推到最后；脚本检出负载会自己标「不可信」，**那时的数字不得据以写配额**。

各子代理用**自己的 scratch 前缀**。

> **触库并发为什么不能无脑加**：并发迁移在 8 路下实测耗时增加约 264%。

**线间不设串行闸。**
跨线条目**不得以同域、同文件、在途为由建立串行依赖**，也不要求他线回执。
**线间只有范围知会**——不阻断、不等待。
**并发控制按线内**：各线自行保证在办条目与子代理不过并发预算。
同文件跨线冲突**按 git 合并处理**。

## 七、复用

**能复用必须复用。**

子代理一经开启即可续用。凡**同一 worktree／分支**、**同一文件白名单**、**同一职能**的后续工作——
返工、补测、复核、增量——**一律续派给原子代理**，保留其上下文与既有证据，**禁另开**。

**新开的正当理由只有三种**：

1. 原子代理**已终止且不可续**；
2. **职能必须独立**（`verifier` 独立于 `impl`／`test`）；
3. **并行扇出且文件白名单互不重叠**。

**派单前先查在册可续者。** 续派返回未送达时方可新开，并在回报中留痕未送达原因。

---

## 八、越权禁止

子代理**永不**执行：

1. `git merge` 或 `git push`；
2. 调用 `accept`（`✅` 由该动作产生）；
3. **直接编辑任务状态文件**——只能经协调器；
4. 装 hooks；
5. 动公约与 `docs/`（除派单明确指派）。

---

## 九、禁空转

**派单双检**：派单前查在册可续者，并**实测目标状态**。
**已落盘、已完成的活不得再派。**

**禁无界等待**：子代理**禁** `sleep`、轮询、`while` 等外部状态等待。
需等条件满足 ⇒ **立即回报派单方**，由派单方在条件达成后续派。

**空转必报**：一回合**零文件改动、零结论**的，须回报根因。
判「不可续」按第七节例外一处理；该空转回合**计入累计额度**。

**小活不单独开局**：≤3 行的行类小活，**并入同批邻接任务，或由派单方单点写**。

## 十、派单模板

逐项填写，**缺项不派**。

```
【条目】T-X-N
【规模】预期文件数 ≤ 6；净新增 ≤ 约 400 行；超限则按互不重叠白名单拆
【白名单】<精确清单——子代理只能动这些>
【不动清单】<明确禁改：生产代码 / 共享文件 / 状态文件 / docs/ / 公约文件 …>
【职能】impl | test | verifier
【复用】派单前查在册可续者；同条目、同分支、同白名单、同职能一律续派；未送达方可新开
【空转】派单前双检；禁 sleep 与轮询；零产物须回报根因并计入额度；小活并批或自办
【门禁】命令原文 ＋ 退出码 ＋ 摘要数字 ＋ 原始输出落盘路径；报「既有红」须附同口径对照
【扇出】按 A ≈ P ÷ T 反推；互不重叠白名单；不触库可任意并行；
        共享文件串行或单点改；触库并发 ≤2（修前）／≤4（修后）；单对话累计 ≤ 10
【回报】条目号 / 分支 / commit / 改动文件 / 门禁命令与退出码与摘要与落盘路径 /
        关键自测数字 / 「我未验证的假设」清单 / 已知边界与残留
【越权禁止】git merge 与 push · accept · 编辑状态文件 · 装 hooks · 动公约与 docs/
```

---

## 十一、上下文纪律

**回报体积是 `T` 的第一约束**，所以回报必须小且可核。

**其一·原始输出落盘，回报只给路径。**
子代理跑门禁的**完整输出写进文件**，回报里只放：命令、退出码、摘要数字、**落盘路径**。
派单方需要细节时**自己去读那个文件**，不让它进回报。

**其二·明细不进回报。**
回报不列逐条日志、不贴堆栈、不抄表格。**要证据，报路径。**

**其三·「我未验证的假设」必须列。**
这一项不是可选装饰——它是派单方**唯一的风险清单**。**缺项退回。**

**其四·查询有界。**
派单方查进度用有界读命令，**不拉全量**（见 `COORDINATION.md` §9）。

**其五·不把明细预读进上下文。**
派单前只读**可认领清单**与**报告**——两者都已是有界输出。

## 十二、派单方自留义务

**其一·独立重跑门禁。** 合入前自己跑一遍，不信自述。

**其二·核掉未验证的假设。** 把子代理的「我未验证的假设」逐条核掉，或转为新条目。

**其三·冲突以实证为准。** 交付物与自己的结论冲突时，以**同口径对照实证**为准，
**不得以子代理自述为据**。

---

## 十三、为什么定这些

三类缺陷在「自己设计判据、自己实现、自己写测试、自己宣称通过」的**自证闭环**下**系统性漏检**：

| 缺陷 | 曾经发生过 |
|---|---|
| 设计假设未验证 | 审计脚本「离线判已落库」出假阳性 |
| 顺序依赖空断言 ＋ 陈旧基座的红被误报为「既有红」 | 基座「证否」拆成两用例 |
| 发现未同批落 `todo/` | 一次 spike 的发现只进归档、未落条目 |

**故**：证据可核不放松，但回报体积必须有界。
