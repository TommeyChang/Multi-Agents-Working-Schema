# 技能：把一条规则变成闸

## 何时用
- 用户给了"必须／禁止"的要求，而你只打算写进文档 ⇒ **停**，先想判据。
- 用户说"规则性的用工具解决""要能量化""单纯靠文字约束力太小"。
- 某条款被违反过（事故复盘、存量缺口）。

## 九步（照做，别跳）
1. **取原件**：找到原始文字与日期（常在工程 `AGENTS.md`／`WORKFLOW.md`／板面）。**不许转述**——转述会漂。
2. **写声明**：「谁 · 在什么条件下 · 算什么」。一句话说得清才配做闸；说不清＝还没想清。
3. **定判据**：能跑的命令或纯函数。判据放**单源** `bg_coordinator/<模块>.py`，`tools/<x>.py` 只做外壳（定位／取数／报）。
4. **选失败方向**：判不了时拦还是放？本体系口径：**假红比没闸更坏**；判不了归属就不许当罪名（记 note 不 BLOCK）。
5. **豁免可数**：允许例外的必须能**被点名列出**（例：`no_closure_path` 由 audit 逐条点名），不许静默消失。
6. **负例必须有**：合成一份违规样本断言必红，再给边界正例（正好等于上限不报）。没有负例的闸＝空绿。
7. **接三面**：能拦的地方全接（提交闸／合并闸／门禁腿／冒烟），拒绝时给**可执行的下一步命令**，不让人猜该找谁。
8. **文档下沉**：加内容先删，超限先删再发；一处权威，别处只留指针；跑预算闸。
9. **登记台账**：在 `bg_coordinator/rulings.py` 把该口径的兑现者改成这个闸；欠账（纯文字口径）上限 6，只减不增。

## 反例（别这么做）
- 判据靠人读、靠自觉、"记得要做"。
- 只在文档里加粗一句"必须"。
- 判据裂成两份（工具一份、文档一份）——必然漂。
- 阈值写死在散文里。`AGENT.md §三` 的体积表就漂过近一倍。
- 超限去抬上限，而不是先删。要抬就写明理由（改一处常量）。
- 只测好路径，不给负例。

## 命令
```bash
python3 tools/context_budget.py            # 固定上下文预算（超了先删）
python3 tools/rule_coverage.py --text      # 还没闸的口径＝欠账清单
python3 -m pytest -q tests/ && python3 -m ruff check . && bash tools/smoke.sh
python3 -m bg_coordinator.cli --root "$R" maws    # Schema ↔ 实现对账
```

## 完成判据（缺一不算做完）
- 判据有单源实现 ＋ 工具外壳，负例与边界正例都在测试里；
- 至少一个**真实面**跑得出来（提交／合并／门禁／冒烟之一）；
- 文档一处权威且预算与台账都绿；
- 提交信息写清：口径来源（谁·何时）＋判据＋负例＋存量影响。
