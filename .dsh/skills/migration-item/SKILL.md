# 技能：迁移类条目收口

## 何时用
改动含迁移件（绑定 §迁移 的 `dir`，本工程 `alembic/versions/`）；或迁移闸报 `[5]`／`[6]`／`[7]`。

## 三个收口点（放号只保证号唯一，保证不了链位唯一）
| 点 | 命令 | 判什么 |
|---|---|---|
| 放号 | `coord reserve --family alembic --holder <人> --task <条目>` | 该族**同时只允许一个在飞占号** |
| 提交 | `python3 tools/commit_gate.py --task <条目> --repo <仓>` | 单 head／父齐／全可达／新增件号单调且父==基线 head／**已落库件未被改** |
| 合并 | `coord merge-request ...`（`merge.py` 闸 4.5） | 同上，对的是**即将落上去的 main head** |

单命令全量版：`python3 tools/migration_gate.py --base origin/main --root "$BG_COORDINATOR_ROOT"`。

## 判据口径
- **已落库 = 该路径在基线树里**（本工程 `origin/main`）；未合入的新件不受保真闸管（那属 `[5]`）。
- **落后 ≠ 改写**：判据对照**分叉点**（`merge-base(base, HEAD)`）——基线自己动过而本分支没动，不拦。
- **删除／改名历史件同罪**：链上别人的父节点会悬空。
- **唯一例外**：剥掉 docstring 后 AST 等价（注释／排版级），闸自己算出并留痕。

## 撞上了怎么办
- **父节点不对／两个 head**：后落地那件把 `down_revision` 改指新的 head，号保持。
- **号被插队**（小于基线最大号）：让号重取——号是资源。
- **已落库件被改写／删除**：**不许改回来当没事**；新开下一 revision 补偿承载，另立条目走 dba 评审 ＋ ops 窗口。
- **簿记（`[7]`）**：件在盘上却无账 ⇒ 去取号；账上 pending 却已有件 ⇒ 该落物。

## 窗口段序（DDL 归 ops）
`停服 → 迁移 → 重铺 → 预检 → 起服 → 验证留痕`；开窗前跑 `python3 tools/preflight.py`。
**dba 只做评审闸与实例运维，不执行 DDL**；评审通过即入库（合并主分支）。

## 反例
- 就地改已落库件"补一列"——已建表不会回流，合入即漂移。
- 在共享主检出跑迁移闸（未提交面是所有人的）。
- 把 `alembic check` 的降级差异当成实现漂移（它不校验降级保真）。
